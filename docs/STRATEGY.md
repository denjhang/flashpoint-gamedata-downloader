# 下载策略与实测数据

**核心结论：不同平台的体积分布差异极大，排序策略直接决定快慢。**
选错了会慢 70 倍。

## 实测数据汇总

所有测试均在 2026-10-24，中国大陆直连（无代理），CDN = Cloudflare。

| 场景 | 并发 | 每文件连接 | 实测速度 |
|---|---|---|---|
| Flash，32 并发 | 32 | 8 | 16.4 MiB/s |
| Flash，32 并发（含其他负载） | 32 | 8 | 11.4–22.2 MiB/s |
| HTML5，**按体积升序** | 12 | 16 | **0.99 MiB/s** ❌ |
| HTML5，**大文件优先** | 10 | 16 | **71.25 MiB/s** ✅ |
| 两盘并行合计 | — | — | 82.7 MiB/s |
| 单连接（curl） | 1 | 1 | 0.7–2.9 MB/s |

> **71 倍差距**：同样是 HTML5、同样 10–12 并发，只因清单排序不同。

## 为什么排序这么关键

### Flash 平台：分布均匀，随便下

平均 5 MiB/个，中位数 5.3 MiB。文件数多但每个都不小，
HTTP 请求开销占比低，**直接高并发即可**。

```bash
python build_manifest.py --platform Flash --out flash.tsv --aria-out aria_flash.txt
bash download.sh flash.tsv /data/fp-flash 32 8
```

### HTML5 平台：极度倾斜，必须大文件优先

| 分组 | 数量 | 占比 | 体积 | 占比 |
|---|---|---|---|---|
| ≥ 10 GiB | 16 | 0.06% | 246.0 GiB | 18.8% |
| ≥ 5 GiB | 43 | 0.16% | 439.8 GiB | 33.5% |
| ≥ 1 GiB | 191 | 0.72% | 728.0 GiB | 55.5% |
| ≥ 100 MiB | 1,288 | 4.9% | **1042.7 GiB** | **79.5%** |
| < 100 MiB | 21,320 | 80.8% | 267.9 GiB | 20.4% |

**如果按升序下（先小后大）**：前 2,300 个文件下完只有 0.17 GiB
（平均 77 KB/个），带宽全耗在 TCP 握手 + HTTP 请求开销上 → 0.99 MiB/s。

**改成降序（先大后小）**：10 个 1–33 GiB 的大文件同时跑，每个 16 连接，
立刻打满带宽 → 71.25 MiB/s。

### 推荐的两阶段流程

```bash
# 生成分片清单 (以 100MiB 为界)
python build_manifest.py --platform HTML5 --split-by 100M --outdir .

# 阶段1: 大文件 (1288 个 / 1042.7 GiB) — 低并发 + 每文件 16 连接
bash download.sh manifest_big.tsv /data/fp-html5 10 16

# 阶段2: 碎文件 (21320 个 / 267.9 GiB) — 高并发 + 每文件 4 连接
bash download.sh manifest_small.tsv /data/fp-html5 48 4
```

阶段1 跑完就能拿到 **80% 的体积**。

## 并发与连接数怎么选

经验法则：

| 文件特征 | 并发 `-j` | 每文件连接 `-x/-s` | 理由 |
|---|---|---|---|
| 碎文件（<10 MiB，数量多） | 高（32–64） | 低（4） | 靠并发数堆吞吐；单文件太小，多连接无意义 |
| 大文件（>100 MiB） | 低（8–16） | 高（16） | 靠单文件多连接打满带宽；并发太高会互相抢 |

`download.sh` 的第 3、4 个参数就是这两个值。

## 磁盘与时间预估

| 范围 | 体积 | 32 并发预计 | 大文件优先预计 |
|---|---|---|---|
| Flash | 794.4 GiB | ~18 h | — |
| HTML5 | 1311.2 GiB | — | ~6 h |
| 全量 | 2.15 TiB | ~40 h | — |

> 注意留出**至少 10% 余量**：`--file-allocation=none` 下 aria2 边下边写，
> 但如果空间不足会导致写失败。另外 `.aria2` 控制文件会占少量空间。

## 断点续传

aria2c 的 `-c` + `.aria2` 控制文件 = 天然续传。中断后**原样重跑同一条命令**：

```bash
bash download.sh manifest_big.tsv /data/fp-html5 10 16   # 再跑一次即可
```

已完整下载的文件会被跳过（`--allow-overwrite=false`）。

## 关于 404

约 **0.2%** 的条目（全量约 400 个）在数据库里仍标记 `Playable`，
但 CDN 上文件已被删除（游戏下架）。

- 这不是下载失败，也不是规则错误
- aria2c 会记录 `Resource not found` 并跳过
- `verify.py` 会把它们列为 `missing`
- 无需处理，若想清理可对比 `_verify_bad.json`

## 校验

```bash
python verify.py /data/fp-flash manifest_flash.tsv
```

实测 200 样本 **200/200 通过**（大小 + SHA-256 全对）。

SHA-256 来自官方数据库 `game_data.sha256`，与 CDN 上的文件一致，
所以这个校验是**权威的**，不是自己算自己。
